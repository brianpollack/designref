Anatomy

ContainerFixed 280px wide, so the menu never changes width while filtering. Height follows the results up to 380px, then the list scrolls under the field.
Filter fieldSearch icon, the field, and a chip naming the issue the menu acts on. A 1px rule separates it from the list.
Group headingNames a group. The letter on the right is the list’s own shortcut for that group (Linear’s S, A, L). Hidden when none of its options match.
OptionFour columns: a 16px slot (status glyph, avatar, label dot or icon), the label, a shortcut hint, and a 12px check column that is always reserved, so hints and checks line up across groups. 30px rows.
Active optionFilled row. There is only one: pointer and arrow keys move the same highlight.
MatchMatched characters take the match color on a tinted background. A group heading is highlighted too when the query names the group.
CheckMarks the values the issue already has: its status, its assignee, each of its labels.
Status glyphA ring whose fill shows progress: dashed for Backlog, empty for Todo, half for In Progress, full for Done, struck through for Canceled. Shape differs as well as color. The issue rows reuse it.
Destructive optionLast. Red label and icon, red-tinted active fill.
Empty stateOne line in place of the list when nothing matches.
No disabled optionsCommands that don’t apply are left out rather than dimmed. In a filtered list a dimmed match is noise; Raycast and Linear leave them out too.

Specs

Behavior

Opens onRight-click, Control-click on macOS, long-press on touch, Shift+F10 or the Menu key on a focused issue. Empty space keeps the browser’s own menu.
PlacementTop-left corner at the pointer; flips on whichever axis runs out of room. Same technique as the Right-Click Menu: a zero-size anchor moved to the pointer and showPopover({ source }).
FieldFocused on open by autofocus inside the popover. The query is cleared every time the menu opens.
FilteringCase-insensitive substring of the option label or its group name, so “assignee” lists everyone. Script only sets hidden on options; :has() hides empty groups and swaps in the empty state.
Active optionThe first match after every keystroke. ↑ ↓ move it and scroll it into view inside the list only (scrollIntoView({ container: 'nearest' })), so the page never moves. The pointer moves it too.
RunningStatus and Assignee set the value and close. Labels toggle and stay open, so several can be set in one visit. Actions run and close. The issue row redraws itself from its data attributes.
EscThe first press clears the query, the second closes and returns focus to the issue. Both come free from <input type="search"> inside a popover.
MotionFades in and grows from 98% out of the pointer corner, 110ms, quart ease-out. Closes in 80ms. No motion with reduced-motion set.
DismissEsc on an empty field, a click outside, Tab, or a right-click on another issue (which reopens it there).

Accessibility

KeyDoes
TypingFilter. The first match becomes active.
↓ ↑Move the active option, wrapping at the ends. Focus stays in the field.
EnterRun the active option.
EscClear the filter; on an empty field, close and return focus to the issue.
TabClose the menu and move on.
Shift+F10Open from a focused issue (also the Menu key).
  • This is the APG combobox pattern with a listbox popup, not a menu: role="menu" can’t contain a text field. The field is role="combobox" with aria-controls and an active descendant; options sit in role="group"s named by their headings. cmdk and VS Code’s Quick Open use the same structure.
  • The active option is set through ariaActiveDescendantElement (element reflection), so options need no ids. It is also aria-selected; the issue’s current values use aria-checked.
  • Highlights paint over text without changing the DOM, so screen readers read each label exactly as written. Hints, initials and glyphs are hidden from assistive tech.
  • Gap: the number of results isn’t announced while typing. Add a polite live region (“3 results”) if your audience needs it.
