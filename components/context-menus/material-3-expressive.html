Anatomy

Menu with gapGroups stack with a 2px gap, each its own surface with a level 2 shadow. The menu’s outer corners are 16px; corners that face a gap are 8px. Google: one or two gaps per menu, and none in a scrolling menu. The other layout, “with divider”, keeps one surface and separates groups with dividers.
Group4px padding on all sides, so item fills and highlights never touch the group edge.
Item44px minimum height, 16px side padding, 8px top and bottom. A 20px leading icon sits 12px from the label. Corners are 4px; the first item’s top corners and the last item’s bottom corners are 12px, concentric with the 16px group.
Supporting textOne line under the label in BodyMedium. The item grows to 60px.
Trailing textLabelSmall at the end of the row, usually a keyboard shortcut. Hidden from screen readers.
Selected itemTertiaryContainer fill with 12px corners on all sides, inset rather than full width. The leading icon swaps to a check (Compose selectedLeadingIcon).
Disabled itemOnSurface at 38% for label, icon and text. No state layers; skipped by arrow keys.
Destructive itemM3 menus define no destructive style, and Google’s own apps keep Delete in the label color. This demo uses the Error role; reserve it for actions that can’t be undone.
Color stylesStandard sits on SurfaceContainerLow and suits most menus. Vibrant fills with TertiaryContainer for emphasis; Google says to use it sparingly. In Vibrant, icons turn Tertiary while hovered, focused or pressed.
Baseline menuThe older M3 menu is one surface with 4px corners, 48px items and a full-width selection. Both share the 112–280px width limits.

Specs

Behavior

Opens onA tap or click on the overflow button, or Enter / Space when it has focus. commandfor and command="toggle-popover" do this with no script.
PlacementDirectly below the button with right edges aligned, using the button as the implicit anchor. Flips above it when there is no room below.
MotionScales up from 80% out of the corner nearest the button while fading in, as Compose does. Scale and corner morphs use the fast spatial spring (stiffness 800, damping 0.6: 360ms with about 9% overshoot); opacity and color use fast effects (stiffness 3800, damping 1: 150ms). Both springs are sampled into CSS linear(). No motion with reduced motion set.
StatesHover 8%, focus 10%, pressed 10%, as a layer in the item’s content color. Hover and focus are separate: the pointer does not move keyboard focus.
SelectionSort options are radio items. The chosen one morphs to 12px corners and fills on the springs above, then the menu closes after 250ms.
Shape morphNot built here. Compose also morphs group corners as the pointer moves through cascading submenus: 24px for the active menu, 8px for one that has been left.
Color styledata-color="vibrant" on the popover swaps every color in one place. The segmented button in the demo sets it and reopens the menu.
DismissChoosing an item, Esc, a tap outside, or Tab.

KeyDoes
Enter Space on ⋮Open the menu with focus on the first item. A pointer open focuses it too, without the focus indicator.

EscClose and return focus to the ⋮ button.
TabClose the menu and move on.
  • focusgroup="menu" infers role="menu" and menuitem. Sort options set menuitemradio and aria-checked. Each segment is a named role="group", so the gaps are announced as group boundaries.
  • The button carries aria-haspopup="menu"; the browser reports aria-expanded from the popover state.
  • Focus indicator: the standard M3 indicator is 3dp in Secondary with a 2dp outer offset. Material Web draws it inward on list and menu items, and so does this demo, so it stays inside the 4px group padding. It grows to 8px and settles at 3px over 600ms.
  • Contrast: OnSurface on SurfaceContainerLow is 15.5:1 light and 13.2:1 dark. Vibrant labels are 13.2:1 and 7.2:1; selected Vibrant labels 6.5:1 and 7.8:1. Error on either container is at least 5:1.
  • Not built: ↓ on the button to open the menu (WAI-ARIA menu button pattern) and typeahead.
