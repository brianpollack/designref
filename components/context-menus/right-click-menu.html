Anatomy

ContainerPopover surface with a 1px hairline border and a two-layer shadow. Inner padding inset so item highlights never touch the edge.
Section labelOptional. Names what the menu acts on (the file name) or titles a group. Not focusable.
ItemThree columns: a fixed 16px icon slot, the label, and an optional shortcut pushed to the end. The slot is reserved even without an icon so labels align.
ShortcutSecondary color, tabular figures, hidden from screen readers.
Separator1px rule between groups of related commands, never at the top or bottom.
Checkable itemCheck mark replaces the icon in the slot. Radio groups share one label above them.
Disabled itemDimmed and skipped by arrow keys, but kept in place so the menu’s shape doesn’t change.
Destructive itemLast, after a separator. Red label and icon, red-tinted highlight.

Specs

Behavior

Opens onRight-click, Control-click on macOS, long-press on touch (the browser fires contextmenu), Shift+F10 or the Menu key.
PlacementTop-left corner exactly at the pointer. If the menu would overflow, it flips to the other side of the pointer on that axis, or both.
MotionFades in and grows from 96% scale out of the corner nearest the pointer, 120ms, strong ease-out. Closes in 90ms. No motion with reduced-motion set.
PointerHighlight follows the pointer. Leaving the menu clears the highlight. A click runs the command and closes the menu.
Checkable itemsToggle, stay open for 250ms so the new check mark is visible, then close.
ContextDifferent targets get different menus: a file gets file commands, empty space gets folder commands. The target stays highlighted while its menu is open.
DismissEsc, a click or right-click anywhere else (which reopens at the new spot), Tab, or focus leaving the window.

Accessibility

KeyDoes
↓ ↑Move between enabled items (native focusgroup). From a pointer open, the first press enters the menu.
Home EndFirst and last item.
Enter SpaceRun the focused command, or toggle a checkable item.
EscClose and return focus to where it was (native popover behavior).
TabClose the menu and move on. Focus is never trapped.
  • focusgroup="menu" infers role="menu" on the panel and menuitem on each button, so the markup stays plain. Checkable items still set role and aria-checked explicitly.
  • With no trigger button, the menu is named with aria-label. Separators are real <hr> elements, which the browser exposes as separators.
  • Shortcut text is aria-hidden. When the shortcuts really work in your app, add aria-keyshortcuts to the item.
  • Not built here: typeahead (jump to an item by typing its first letters). Add it if menus run past about ten items.
