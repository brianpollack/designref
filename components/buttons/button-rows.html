Anatomy

Equal-width rowA CSS grid of 1fr columns. Every button is the same width, whatever its label, and the row fills its container. For three to five peers with short labels, such as message actions.
Icon-over-label barThe same grid with a column button: 24px-ish icon over a 12px label. It lets five peers fit a narrow width and keeps each one a large target.
Steps rowThe dismissing action alone at one end; the forward pair (Back, Next) together at the other. Carbon’s progress modal does this: Cancel far left, Previous and Next on the right.
ToolbarIcon buttons in one bordered strip, 2px apart, with a divider between groups. One tab stop for the whole strip; arrow keys move inside it. APG advises role="toolbar" for three or more controls.
Wrapping rowflex-wrap with one gap for both directions. Buttons keep their natural width and drop to a second line when they run out of room.
Collapsing rowAt a narrow container width labels become visually hidden and buttons become square icons. The label stays in the DOM, so the name does not disappear.
Overflow rowItems have a priority. As the container narrows the lowest priority leaves the row and appears in a More menu, one item in exactly one place. The primary action never leaves.

Making many buttons look good

One height, one gapEvery button in a row shares a height, and one spacing value is used across and down. Apple: same-size buttons signal a coherent set, and style, not size, ranks them.
One loud buttonEven among five, only one gets the primary fill. Fluent: with more than two buttons of equal priority give all of them neutral backgrounds. Carbon: do not use two high-emphasis buttons in a group, and with more than three actions prefer tertiary or ghost.
Group by meaningSeparate the destructive or dismissing action from the forward ones (the steps row), and divide unrelated tool groups with a divider, not extra space alone.
Too many?Carbon: more than three actions belong in a menu button or a toolbar. A toolbar of icons is for frequent, well-known actions; Apple asks for familiar symbols and a text label on every icon for assistive technology.
Short labelsOne word where you can. A long label breaks equal widths first.
SizeRows of 40px buttons clear WCAG 2.2’s 24px minimum; for touch use 44px or more (Apple and WCAG’s enhanced level) or Material’s 48dp.

Specs

Our own values. The breakpoints are container widths of the dashed box, so the same row is correct in a window, a panel or a card.

Behavior

Container, not windowThe dashed box is a container-type: inline-size box, so @container rules respond to the space the row actually has. A browser-width query would be wrong inside a narrow side panel.
Overflow menuThe More button and its menu are shown only when something has moved. The menu is a popover anchored to the button with CSS anchor positioning; the button needs no script.
Toolbar keysLeft and Right move, with wrap; Home and End jump; Tab leaves the strip. Toggle buttons (bold, italic) use aria-pressed and keep the same label whether on or off.
Equal widthsGrid columns share the row equally, so a long label widens the whole row’s buttons, not just one. Keep labels short or use the wrapping row.
Reduced motionHover and press transitions stop.
Forced colorsEvery button gets a visible ButtonText border; a pressed toggle uses Highlight.

  • A row of related buttons is a group with a name; a toolbar is role="toolbar" with a name and a roving tab stop. focusgroup did nothing for tabs in Chrome 156 and was not tested for toolbars, so the keys are scripted.
  • Icon-only and icon-collapsed buttons keep an accessible name: the label stays in the DOM, visually hidden.
  • The More menu is a simple popover of buttons. It is marked role="menu" for the demo; a full menu needs the arrow-key behavior from Overflow Action Menu.
  • Toggle buttons keep one label and change only aria-pressed, as APG’s button pattern requires; changing the label as well would double the signal.
