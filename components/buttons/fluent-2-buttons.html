Anatomy

ButtonA button with an optional icon and a label, 1px border, 4px corners. Sizes: small 24px, medium 32px (default), large 40px; the height comes from padding plus line height, not a fixed value.
Appearancesecondary (default, neutral fill and border), primary (brand fill), outline (transparent fill, neutral border), subtle (no fill or border until hover) and transparent (no fill ever; the label turns brand on hover).
Icon20px (large 24px) before the label. Regular at rest; subtle and transparent swap to Filled on hover, and any checked toggle shows Filled. Icon-only buttons are square: 24, 32 and 40px.
Shaperounded (size radius, default), circular and square.
ToggleA button with a checked state. Checked secondary and subtle take their Selected fills; checked primary takes colorBrandBackgroundSelected. Outline and transparent toggles are not built here.
Split buttonA primary action beside a 24px-minimum menu button, sharing one edge. The action is not repeated in the menu, and each menu item uses the full phrase (“New event”).
Dialog actionsThe footer row of a dialog: a flex row with an 8px gap, aligned to the end. The primary is first in the DOM, so it sits left of Cancel.
Not builtCompoundButton (a secondary line under the label, padding and icon values are in the sources), MenuButton, disabledFocusable, and the forced-colors rules.

Specs

Behavior

HierarchyOne primary button in a layout, for the most important action. With more than two buttons of equal priority, make all of them neutral. With many minor actions, use outline, subtle or transparent on all of them.
PlacementThe primary goes on top of, or to the left of, the other actions; in right-to-left languages, to the right.
Hover and pressFill, border and label each move to the Hover token, then the Pressed token. Primary keeps a transparent border; subtle and transparent show only a label (and fill, for subtle) change. Subtle turns only the icon brand; transparent turns the label and the icon.
FocusKeyboard focus only: a transparent 2px outline (seen in forced-colors mode), the border and a 1px inset ring in colorStrokeFocus2. Primary adds shadow2 and a 2px white inner ring, which drops on hover. Small buttons use 2px corners and large 6px while focused.
DisabledDisabled fill, border and label for every appearance, except that outline, subtle and transparent stay unfilled and primary, subtle and transparent lose the border. No hover. Fluent says to show a tooltip stating what is unavailable and why.
MotionBackground, border and color ease over 100ms on curveEasyEase; under reduced motion the duration is 0.01ms.
Dialog actionsAlert dialogs can be dismissed only by a footer button. At 480px and below the row becomes a column and the primary stays on top. Here that is a container query on the dialog so both cases show together; Fluent uses a viewport media query.
Action countFluent’s sources disagree. The Dialog page says the footer holds up to three actions and the storybook best practices say no more than three buttons; the storybook note on fluid says a dialog should have no more than two. The demo shows two.
LabelsA single active verb, sentence case, no end punctuation. “New X” to create, “Add X” for an existing item. In a dialog, answer the title (“Delete this file?” gets Delete file and Cancel). Next and Previous, not Continue and Back. Cancel discards; Close leaves the task unchanged; never use OK to dismiss an error.

Accessibility

KeyDoes
TabMoves between buttons; a split button is two stops, the action then the menu button.
Enter SpaceActivates the button; on a toggle it flips aria-pressed; on the menu button it opens the menu.
↑ ↓In the split menu, moves between items. Esc closes it and returns focus to the menu button.
  • Every icon-only button has an aria-label; icons inside labelled buttons are decorative.
  • A toggle uses aria-pressed. Fluent asks for a change in text, icon or color that shows both the state and the action; here the Filled icon and the fill change together.
  • Text must reach 4.5:1 and icons 3:1 in every state; the border has no requirement. Disabled buttons are exempt.
  • Small buttons are 24px and the split menu button about 31px, so they meet the WCAG 2.2 24px minimum but not the 44px recommendation.
