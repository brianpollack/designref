Anatomy

ButtonA native button, 44px tall, with every state’s label stacked in one grid cell. The widest label sets the width, so idle, loading, success and retry never move the layout. Only the current label is visible and exposed to assistive tech.
SpinnerAn icon left of the label, turning at 800ms. NN/g’s button-states article puts the spinner left of the label and says the button may turn into a check mark on success.
FillDeterminate progress is a layer behind the label whose width is the --p custom property. Script sets --p; CSS animates between updates. The percentage text carries the value, so color is not the only signal.
Status lineA p with aria-live="polite", present and empty before anything happens. It is the visible caption and the announcement in one. MDN’s aria-live page recommends polite for “Saving…” and “Saved”, and an existing empty region.
Hold to confirmAn outline button in the destructive color. While held, a tint fills it over 1.2s; reaching the end confirms, releasing cancels. The CSS animation is the timer, so there is no second value to keep in step.
Type the nameAn input and a delete button that stays aria-disabled until the text matches. NN/g: for the most dangerous operations, require a nonstandard action such as typing a word.
Undo toastA popover="manual" with Undo and Dismiss. Dismiss is an invoker button, commandfor with command="hide-popover", so it needs no script. It fades in with @starting-style and leaves with display and overlay transitions using allow-discrete.

Specs

Behavior

Which patternNN/g (confirmation dialogs): confirm only serious or irreversible actions, since routine confirmations train people to click through. Where an action can be undone, offer undo instead. Where it cannot, use hold or typed confirmation, and name the specific item.
Feedback timingNN/g (response times): 0.1s feels instant, so show nothing. Past about 1s, show that work is happening. Past about 10s, show percent-done and a way to cancel. When progress is unknown, a spinner is the last resort. The progress demo shows percent because it knows it.
Repeat clicksWhile loading, the button is not disabled: it keeps focus and its state is announced. Script returns early on any click that arrives during loading.
SuccessCheck and “Saved” for 1.8s, then idle. The status line says it too.
FailureThe button becomes Retry in the failure color and the status line says what went wrong. It stays until the next click; it does not time out.
HoldPointer down or Space / Enter down starts the fill. Release, leaving the button, losing focus, or touch cancel stops it and the fill resets. A quick click does nothing. This hold pattern is our design: none of the sources read for this page describe it, and NN/g’s confirmation page lists typed confirmation and undo as alternatives.
Reduced motionThe spinner stops (the label still says what is happening) and transitions are off. The hold fill stays, because it is progress, but moves in six steps.
Forced colorsBackgrounds are removed, so the fill becomes a 4px Highlight bar along the bottom, and the aria-disabled button gets GrayText, as MDN suggests.
Why script sets the fillanimation-timeline was read on MDN for scroll() and view() timelines only, so it suits a scroll-progress fill, not a time or upload one. Work-driven progress needs a value from script.

Accessibility

KeyDoes
TabReaches every button, including the one that is aria-disabled and the one that is loading.
Enter SpaceActivate (APG button pattern). On the hold button they must be held for 1.2s.
  • aria-disabled or disabled. MDN: aria-disabled only exposes the state; it does not change focusability or suppress anything, so script must block the action, and it adds no styling. Native disabled removes the control from the tab order and the form. NN/g’s button-states article recommends aria-disabled="true" so the button stays reachable and is announced as inactive. This page uses it for the typed-name button, with an explanatory status line when clicked early.
  • Loading. Use a polite live region for the message. MDN documents aria-busy for live regions and widgets, as a way to hold announcements until several updates finish; the button here sets it too, but how each screen reader treats it on a button is not covered by the page, so test with your target tools. The accessible name follows the state, so a focused button reads “Saving…” then “Saved”.
  • Progress. The region is updated at quarters, not every 5%, to avoid a stream of announcements.
  • Hold is never the only path. Pair it with the typed-name or undo pattern for people who cannot hold a control, and say how long on the page.
  • Targets are 44px (WCAG 2.5.8 asks 24px; 2.5.5, AAA, asks 44px). Focus ring is 2px, 3px off the edge. Every state’s label is 4.5:1 or better on its fill.
  • The toast times out after 8 seconds in this demo. Timed content needs a way to keep it; a production version should pause the timer on hover and focus.
