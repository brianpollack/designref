Anatomy

ContainerA button (or an a that navigates). 40px high by default, 8px corner, 1px border that is transparent except on secondary. Sized by height and side padding, never by a fixed width, so a longer label never clips.
Label14px, line height 20px, weight 500 in every state, so a state change never reflows. One or two words; a verb for the outcome (“Save”, “Delete”).
Icon18px, 8px from the label, on the leading side for creating or adding and the trailing side for going somewhere. An icon-only button is square and needs an aria-label.
PrimarySolid accent fill. The one thing to do here. One per view or per dialog.
SecondaryNeutral fill and a border. The other things to do.
TertiaryNo fill; accent text that gains a wash on hover. For minor actions in dense places, and for several equal actions side by side.
DestructiveSolid red fill. Only for an action that deletes or cannot be undone, and never the first thing a keyboard user lands on by default.
LinkUnderlined accent text with no box. For navigation that sits in a sentence or a footer, not for actions.
StatesRest, hover, pressed, focus, disabled and loading. Hover and pressed are the base color mixed with black (light) or white (dark) by 12% and 22%, so one token set yields every state.

Specs

These are our own values. Compare each design system’s own numbers on its page: Material 3, Fluent 2, Carbon and Apple-style.

Behavior

HierarchyRank by style, not size. Every major system says to keep the loudest style rare: Apple, one or two prominent buttons per view; Fluent, one primary per layout; Carbon, one primary per page. Material’s rule is the same idea: the more important the action, the higher its emphasis.
Equal-priority actionsFluent: with more than two buttons of equal weight, give all of them neutral backgrounds. Carbon: more than three actions, prefer tertiary or ghost. See Button Rows.
LabelsSentence case, active verb, no end punctuation (Fluent). Apple asks for title-style capitalization. They disagree: pick one for the product. Say what happens: “Delete file” beats “OK”.
HoverA slight darkening. NN/g suggests starting it after a short delay (150–200ms); here it is a 120ms color transition. Hover is never the only way to find an action.
PressedA deeper tone and a 1px nudge, within about 100–150ms. Apple: always include a press state on a custom button.
FocusA 2px accent ring 2px off the edge, for keyboard focus only (:focus-visible). The offset keeps it clear of the fill so it reads on every variant.
DisabledUse native disabled when the control should leave the Tab order. Use aria-disabled="true" when it should stay focusable so a tooltip can explain why; you must then stop the click yourself, because aria-disabled changes nothing about behavior.
LoadingKeep the label and enabled look (NN/g), add a spinner before it, and keep the width. Ignore repeat clicks in script; the button itself stays focusable. See Loading and Confirming Buttons.
Size and spacingWCAG 2.2 requires at least 24px; its enhanced level and Apple say 44px; Material says 48dp. The small size is 32px high, so give touch layouts the medium or large size.
Forced colorsBackgrounds disappear, so every variant gets a ButtonText border and disabled becomes GrayText.
Reduced motionTransitions and the spinner stop; the spinner stays as a static ring.

Accessibility

KeyDoes
Enter SpaceActivate. A native button does this with no script; an a only responds to Enter.
TabMove to the next button. Native disabled buttons are skipped.
  • Use a real button for actions and an a for navigation. Inside a form a button defaults to type="submit"; set type="button" for anything else.
  • Text contrast is at least 4.5:1 on every fill, both themes. Disabled controls are exempt. The secondary border is only 1.6:1, which WCAG 1.4.11’s 3:1 would flag if the border were the only thing marking the button; here the fill and label do that, so keep the label contrast high and do not rely on the border.
  • State is never color alone: focus adds an outline, loading adds a spinner, disabled changes the cursor and the label.
  • Icon-only buttons need a name (aria-label). A destructive action should say what it deletes.
  • aria-busy on its own does not announce anything; pair a loading button with a polite live region (see the loading page).
