Anatomy

Channel headerThe channel name and a one-line topic, and nothing else.
Message listAn ol with role="log" that scrolls. When it is short it sits at the bottom; when it is long the newest message is in view and older ones are above.
Date dividerA pill on a hairline that sticks to the top while that day’s messages scroll beneath it.
New lineA single accent hairline labelled New above the first message you have not seen.
MessageAvatar, sender, time, then the body. Follow-up messages from the same sender close behind it drop the avatar and name and show their own time in the gutter on hover.
Body extrasA mention is a tinted run of text. A link in the body gets a preview card with a 3px rule on its left: title, one line of description, the host.
ReactionsPills under the message: an emoji and a count. Yours is tinted and outlined. The add button appears with the hover toolbar.
Thread linkUnder a message that has replies: up to a few repliers’ avatars, the reply count, and when the last one arrived. It opens the thread beside the channel.
Hover toolbarThree actions for the message under the pointer or focus: react, reply in thread, more. It appears on hover and on keyboard focus within the row.
ComposerOne bordered box, one line tall until text makes it grow, then an action row: attach, emoji, mention, and send. See Message Composer for the full box.

Specs

Slack and Discord publish no pixel values for their message rows, so the sizes here are our own choices, not theirs. Behavior (grouping, hover actions, keys) follows what their help pages document.

Behavior

New messageAppended at the end. If the reader is at the bottom, the list follows it; if they have scrolled up to read, it must not move them and a “jump to newest” control appears instead.
Loading historyOlder messages are inserted above. overflow-anchor (on by default in Chrome) holds what the reader is looking at in place while they arrive.
GroupingThe server decides, because it knows the clock: a message from the same sender shortly after the previous one is sent with .cont. Neither Slack nor Discord documents the window; pick one (five minutes is common) and apply it the same everywhere.
SendEnter sends; Shift+Enter starts a new line. Slack documents Shift+Enter and offers a preference to swap them. Whatever the box holds is shown as text, never parsed as HTML.
ReactionA pill toggles your own reaction and changes its count by one. Removing the last one removes the pill.
ThreadOpens a second pane on the right, with the original message on top and replies below. “Also send to channel” puts a reply in both places, as Slack does.
Long historyFor thousands of messages add content-visibility: auto with contain-intrinsic-size: auto 56px to rows, which skips off-screen layout. It clips overflow, so keep each row’s toolbar inside the row, as this demo does.

Code

Accessibility

KeyDoes
↑ in the empty boxMove to the newest message.
↑ ↓ on a messagePrevious and next message; ↓ from the last returns to the box.
Tab on a messageReach its toolbar, reactions, thread link and links.
EscBack to the box.
  • The list is role="log" with a name: it has an implicit aria-live="polite", so a new message is read when the user is idle and does not interrupt typing. MDN names chat logs as the use case.
  • It is not role="feed". The feed pattern is for content that loads at either end and expects Page Up and Page Down between articles; a chat log has live additions and its own keys.
  • Do not use flex-direction: column-reverse to pin messages to the bottom. MDN warns it separates visual order from DOM order, which breaks reading and Tab order. Here margin-top: auto on the first item does the job.
  • Each message has an aria-label of sender and time so focusing it reads a summary, as Slack’s screen-reader mode does. Avatars are decorative and hidden.
  • Unread is never color alone: bold plus a count, with an accessible label on the count.
