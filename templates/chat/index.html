Core libraries

The modern stack

Chat looks like it needs a framework. In current Chrome most of it is CSS and attributes.

  • role="log" makes the message list a live region that announces additions politely and in order. MDN names chat logs as its use. It is not role="feed", which is for content that loads at either end and expects Page Up and Page Down between articles.
  • field-sizing: content grows the composer with its text, between a min and a max height. No resize observer, no measuring.
  • :has() does the work chat apps usually do in script: it tightens bubble corners by reading the next sibling, shows the avatar only on the last bubble of a run, swaps the microphone for send once there is text, and enables the send button.
  • Popover and anchor positioning open the emoji picker and the mention list above the box, and the call chat panel from its button with commandfor and no script.
  • Scroll anchoring (overflow-anchor, on by default) holds the reader’s place while older messages load above, and content-visibility: auto skips layout for off-screen messages in a long history.

Pin messages to the bottom with margin-top: auto on the first item, not flex-direction: column-reverse: MDN warns the reverse splits visual order from DOM order, which breaks reading and Tab order.

What still needs script: sending and rendering the new message, following the newest message only when the reader is at the bottom, reading the caret to open an @mention list, key handling for moving between messages, and anything that talks to the network. Message text must go in with textContent, never as HTML.
